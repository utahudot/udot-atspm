# ATSPM documentation setup

The root `documentation.json` assigns configuration sections to six service pages
and enables the shared structured log reference. The shared generator lives in
`opensourcetransportation/atspm-documentation-generator`; no local generator copy
or Python/.NET installation is needed to run the GitHub workflow.

Push source or map changes to `main`. The
`.github/workflows/update-documentation.yml` caller uses generator `main`, builds
a strict site preview, and proposes meaningful changes in a documentation PR
against `main`. Download `documentation-preview` from the Actions
run, review the changes, and merge the PR. Generated files in `docs/autogenerated`
belong to the generator and should not be edited by hand.

The repository must allow Actions to create pull requests and access the shared
generator. GitHub only shows manual dispatch when the caller exists on the
default branch; during branch development, pushing triggers it. Add real cloud
team entries to the target branch's `.github/CODEOWNERS` if automatic review
requests are desired. The Pages caller described below creates a reviewed site preview; website publication remains disabled.

To move to another branch later, change the push branch, source-branch, and
target-branch together. A full reviewed generator commit SHA can replace `@main`
to freeze the tooling version.

## Current coverage

Configuration pages cover the locally registered types and named database
contexts. Logging covers structured LoggerMessage declarations in
`Atspm/Infrastructure/LogMessages`; the duplicate event-ID allowlist records
existing intentional duplicates. The log reference is shared across services.
Ordinary ILogger calls outside that folder are not indexed by this setup.

Jwt, Oidc, and GitHubReleaseConfiguration use the repository's existing
documentation-only models under docs/configuration-models. Keep
these models aligned with their runtime consumers. Other direct IConfiguration
reads and package-only types without local models are not discovered. A
successful build does not prove complete runtime configuration coverage or
validate deployed values.

## Pages publication

The .github/workflows/publish-documentation-pages.yml caller uses the shared
Pages workflow in opensourcetransportation/atspm-documentation-generator at main.
It watches docs/autogenerated changes merged into main and sets
docs-branch to main with publish disabled. The shared workflow validates and builds committed documentation into the
documentation-pages-preview artifact. It does not regenerate or publish
unreviewed source changes. publish remains false because restricted Pages
hosting has not been enabled. Website audience and hosting are configured separately.

Commit the Pages caller to main before merging the documentation
PR. Configure this repository's GitHub Pages source as GitHub Actions and allow
only main in the github-pages deployment environment. The Pages
workflow run and environment deployment show the website URL after publication.
If the generated documents were merged before the caller was installed, run the
publisher manually from main once available, or merge the next
documentation update. GitHub only exposes manual dispatch when the caller also
exists on the default branch.

Choose the intended website audience before enabling hosting: a private
repository does not automatically produce a private Pages site. Restricted
Pages hosting requires an eligible GitHub Enterprise organization. Adding this
caller locally does not change remote visibility or activate hosting.

When moving to another publishing branch, update the publisher's push branch
and docs-branch together with the generation workflow's source/target settings.

## Main-based branch migration

This setup targets opensourcetransportation/atspm main. Both caller workflows
use opensourcetransportation/atspm-documentation-generator at main. The changes
are prepared on Code-Documentations-FromMain for review before merging to main.
The source-branch, target-branch and docs-branch inputs all target main.
No Avenue fork is required by the documentation integration.


Code-Documentations-FromMain starts at origin/main 5c7d9628 and cherry-picks only
the shared generator setup and Pages caller from the old documentation branch.
Application source remains identical to that main revision. The API documentation
models are kept under docs/configuration-models, outside application projects;
they were carried over from the original branch without restoring old generator
code or changing application behavior. Keep these manual models aligned with
runtime authentication and GitHub release configuration.

The generated references are rebuilt against this branch's main-based source.
Because main had no documentation baseline, the migration establishes a fresh
configuration baseline rather than reusing the Staging-based snapshot.
